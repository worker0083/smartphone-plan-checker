# au/UQ 乗り換え提案ツール：画面構成と実装の進め方

- 役割分担：**クロ（調査チーム）**＝料金データ（`data/carriers.json`）の調査・更新／**Claude（実装チーム）**＝データを読んで計算・表示する画面
- データ仕様：[`data/README.md`](../data/README.md)・[`data/carriers.schema.json`](../data/carriers.schema.json)
- 土台：今の乗り換え診断（`au-uq/`、v2.8.0）の計算と画面を引き継ぐ。料金だけを `plans.js` から `data/carriers.json` に移す

## 表示のルール（全画面共通）

- 金額は **税込のみ**
- 割引後の金額には **必ず条件を横に出す**（例：「1,628円 ／ 自宅セット割（ネット＋電話）＋au PAYカード払い」）。最安の数字だけを大きくしない
- 期間限定の割引は「1年目」「13か月目から」を分けて出す
- `checked_at` が古いプランには印：黄「確認から◯日」／赤「要再確認」。`confidence: estimate` は「目安」
- 操作はタップ中心。数字の入力はテンキー（`inputmode="numeric"`）、選択肢はボタン
- 文字は本文17px以上、金額は24px以上、ボタンは高さ48px以上
- **片手操作**：主なボタンは画面の下（親指が届く位置）に固定。iPad横向きでは左右2画面（今の v2.8 の形）

## 1. ヒアリング（質問を1画面に1つ、下の「次へ」で進む）

```
┌──────────────────────────┐
│ ●●○○○  2 / 5  家族構成           │ ← 進み具合
│                                    │
│  何人で見直しますか？              │
│  ┌────┐┌────┐┌────┐      │
│  │ 1人 ││ 2人 ││ 3人 │ …     │ ← 大きいボタン
│  └────┘└────┘└────┘      │
│  18歳以下の人  [ 0 ][ 1 ][ 2 ]…    │
│                                    │
│ ┌────────┐┌───────────┐ │
│ │  戻る  ││      次へ        │ │ ← 下に固定
│ └────────┘└───────────┘ │
└──────────────────────────┘
```

| 手順 | 聞くこと | 入力のしかた |
|---|---|---|
| 1 | 家族構成（人数・18歳以下・60歳以上） | 数のボタン |
| 2 | 1人ずつ：今のキャリア → プラン → 月額 | キャリアのボタン → データにあるプランの一覧（受付終了プランも）→ テンキー。月額が分からなければ「プランから計算」 |
| 3 | 1人ずつ：データ使用量・通話 | 1／3／5／10／20／30GB／無制限／わからない、通話は3択 |
| 4 | 自宅の光回線（会社・電話の有無・月額） | 会社のボタン → はい/いいえ |
| 5 | 端末：分割の残り（月額×残り回数）・機種変更したいか | テンキー＋回数ボタン、はい/いいえ/未定 |

- どの画面でも「スキップ」できる（分からない項目は計算から外し、結果に「未入力」と出す）
- 入力は端末内に一時保存し、更新や戻るで消えない（今の v2.8 と同じ）

```
┌──────────────────────────┐
│ [  提案シートを作る  ]                 │ ← 下に固定

```

- スマホ縦：3つのカードを横スワイプ（提案を真ん中に表示）。iPad横：3列で並べる
- 他社候補は、データにあるキャリアから **同じ条件で安い順に2〜3社**（au・UQ 以外）。「他社の方が安い」場合もそのまま見せる
- 各金額をタップすると、割引の内訳と条件・出典（公式ページへのリンク）・確認日が開く
- 端末の分割残債は、どの選択肢でも払い続ける額として別の行に出す（月額比較には混ぜない）

## 4. 実装の進め方

各ステップは公開できる単位にし、毎回 iPad（横・縦）とスマホの画面で自動テストします。

| # | 内容 | 担当 | 終わりの目安 |
|---|---|---|---|
| 0 | このスキーマに合意 | ユーザー・クロ・Claude | スキーマ 1.0 確定 |
| 1 | **データの読み込みと自動チェック**：`data/carriers.json` を読む仕組み、スキーマ検査（GitHub Actions）、確認日の印。今の au・UQ の料金を移してクロに確認してもらう | Claude（移し替え）→ クロ（確認） | 今の画面が JSON から同じ金額を出す。`examples` が全部一致 |
| 2 | **計算を汎用化**：段階制・回線数別・期間限定・併用不可を、キャリアごとの書き方でなくデータの規則で計算 | Claude | au・UQ と、クロが入れた他社1社で `examples` が一致 |
| 3 | **他社のデータ**：docomo（eximo・irumo・ahamo）、SoftBank、Y!mobile、LINEMO、povo 2.0、楽天、IIJmio、mineo、日本通信 | クロ | 各社の `examples` が一致 |
| 4 | **ヒアリング画面**（1画面1問・下に固定のボタン） | Claude | スマホ片手で最後まで入力できる |
| 5 | **比較画面**（3列／スワイプ・条件の表示・確認日の印・他社候補） | Claude | 他社データが入った分から自動で出る |
| 6 | **提案シート**（印刷・PDF・画面表示） | Claude | A4 1枚に収まる |
| 7 | 店頭で試して直す | ユーザー | — |

ステップ1・2（Claude）とステップ3（クロ）は並行で進められます。

## 決めてほしいこと

1. **公開場所**：今の乗り換え診断（`/au-uq/`）を作り替えるか、別の場所に新しく作るか（おすすめ：同じ場所で作り替え、今の版は `/au-uq/v2/` に残す）
2. **地域**：光回線・でんきは今は関西向け。全国にするか、関西のままか
3. **古さの基準**：黄 30日・赤 60日 でよいか
4. **主に使う画面**：スマホ縦（片手）と iPad 横のどちらを優先するか（両方対応するが、作り込みの順番を決めたい）
5. **最初の au・UQ データ**：今のツールに入っている料金（2026年11月に公式で確認済み）を Claude が JSON に移し、クロが確認する形でよいか（データ更新はクロ担当のまま）
6. **クロの更新方法**：GitHub で `data/carriers.json` を直接編集できるか。できない場合は、受け渡しの形（スプレッドシートなど）を決めたい
